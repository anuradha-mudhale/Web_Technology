1.difference between package.json and package-lock.json

--->“When we run npm init, a package.json file is created. It stores basic information about the 
project such as name, version, description, main file, and scripts. Essentially, it keeps the metadata of the project.
When we run npm install express, a package-lock.json file is automatically created. It locks the exact versions of all installed dependencies, including sub-dependencies, and provides detailed information about them. 
This ensures that everyone working on the project uses the same versions of packages.”

4.types of routing

--->“In Express.js, routing is how we define how the server responds to client requests at different URLs. 
There are mainly four types of routing.”

1.Basic Routing – Fixed URLs that return a response.
Example: app.get('/home', (req, res) => res.send('Home Page'));
2.Route Parameters – Dynamic URLs with variables.
Example: app.get('/user/:id', (req, res) => res.send(req.params.id));
3.Query Strings – Optional data sent in URL using ?key=value.
Example: /search?term=books → req.query.term
4.Express Router (Modular Routing) – Organizing routes in separate files for cleaner code.
Example: const router = express.Router(); router.get('/', ...)

5. get,post,put,delete,patch difference

1️⃣ GET
Purpose: To read/fetch data from the server.
Does it change data? ❌ No, it’s safe.
Example: Get all users from database.
app.get('/users', (req, res) => {
    res.send("Fetching all users");
});
URL example: /users

✅ Use case: Displaying data, like home page, profile, product list.

2️⃣ POST
Purpose: To create new data on the server.
Does it change data? ✅ Yes, it adds new data.
Example: Add a new user.
app.post('/users', (req, res) => {
    const newUser = req.body; // data sent from client
    res.send(`User created: ${newUser.name}`);
});
URL example: /users
Body: { "name": "Anuradha", "age": 20 }

✅ Use case: Signup forms, adding products, submitting forms.

3️⃣ PUT
Purpose: To update/replace a full existing resource.
Does it change data? ✅ Yes.
Example: Update a user completely.
app.put('/users/:id', (req, res) => {
    res.send(`User ${req.params.id} updated completely`);
});
URL example: /users/101
Body: { "name": "Anuradha", "age": 21 }

✅ Use case: Replace the entire record with new data.

4️⃣ PATCH
Purpose: To update/modify part of a resource.
Does it change data? ✅ Yes.
Example: Update only age of a user.
app.patch('/users/:id', (req, res) => {
    res.send(`User ${req.params.id} updated partially`);
});
URL example: /users/101
Body: { "age": 22 }

✅ Use case: Partial updates, like changing password, updating profile picture.

5️⃣ DELETE
Purpose: To delete a resource from the server.
Does it change data? ✅ Yes.
Example: Delete a user.
app.delete('/users/:id', (req, res) => {
    res.send(`User ${req.params.id} deleted`);
});
URL example: /users/101

✅ Use case: Removing items, accounts, posts, etc.

💡 Quick Memory Tip (Fresher friendly):
GET → Grab/fetch
POST → Push/create
PUT → Replace/Update whole
PATCH → Partial update
DELETE → Remove

Why do we use middleware in Express.js?

Middleware functions are used to process requests before they reach the final route handler or before sending the response.

They act as a bridge between the request and response cycle.

Common purposes:
Authentication (checking user login)
Validation (checking input data)
Logging (tracking requests)
Modifying request/response

👉 Interview answer:

Middleware is used to handle and process requests before they reach the route handler, enabling tasks like authentication, validation, logging, and data transformation.

2️⃣ Types of middleware in Express.js
1. Application-level middleware

Used for the entire app or specific routes.

app.use((req, res, next) => {
  console.log("App middleware");
  next();
});
2. Router-level middleware

Used for specific routers.

router.use((req, res, next) => {
  console.log("Router middleware");
  next();
});
3. Built-in middleware

Provided by Express.

app.use(express.json());
4. Error-handling middleware

Handles errors in the app.

app.use((err, req, res, next) => {
  res.status(500).send("Error occurred");
});
5. Third-party middleware

External packages like:

cors
morgan
body-parser

👉 Interview answer:

The main types of middleware are application-level, router-level, built-in, error-handling, and third-party middleware.

3️⃣ Benefits of middleware
Code reusability – write once, use in multiple routes
Clean architecture – separates logic (auth, validation, etc.)
Security – handles authentication and authorization
Centralized error handling
Logging and debugging made easier
Request filtering and control

👉 Interview answer:

Middleware improves code reusability, maintainability, security, and helps manage logging, validation, and error handling efficiently.

4️⃣ Where is middleware used in companies?

In real-world backend systems, middleware is used in many critical areas:

🔐 Authentication & Authorization
Checking JWT tokens
Verifying user roles
📊 Logging
Recording API requests
Monitoring user activity
✅ Validation
Validating form data (email, password, etc.)
❌ Error handling
Handling server and application errors
🌐 CORS handling
Managing cross-origin requests
⚡ Rate limiting
Preventing API abuse (e.g., too many requests)

👉 Interview answer:

In companies, middleware is widely used for authentication, logging, validation, error handling, CORS management, and rate limiting in backend applications.

What are Query Parameters?

Query parameters are key-value pairs added to the URL after ? to send data from client to server.

👉 Example URL:

http://localhost:3000/products?category=mobile&price=10000

👉 Here:

category = mobile
price = 10000
🔹 How to access in Express.js?
app.get('/products', (req, res) => {
  const category = req.query.category;
  const price = req.query.price;

  res.send(`Category: ${category}, Price: ${price}`);
});

👉 req.query = object that stores all query parameters

🔹 Key Features
Optional (not mandatory)
Used for filtering/searching
Visible in URL
Multiple parameters allowed
2️⃣ Real-Time Examples (Important 🔥)
✅ Example 1: Search functionality (E-commerce)
GET /products?name=iphone

👉 Use:

Search products by name

👉 Backend:

app.get('/products', (req, res) => {
  const name = req.query.name;
  // filter products based on name
});
✅ Example 2: Filtering data
GET /products?category=shoes&brand=nike

👉 Use:

Filter products by category + brand
✅ Example 3: Pagination (very important)
GET /users?page=2&limit=10

👉 Use:

Show 10 users per page
Page 2 data fetch

👉 Backend:

const page = req.query.page;
const limit = req.query.limit;
✅ Example 4: Sorting
GET /products?sort=price&order=asc

👉 Use:

Sort products by price (ascending/descending)
3️⃣ Where Query Parameters are used in Companies?

👉 Query parameters are heavily used in real-world applications 👇

🔹 1. E-commerce websites
Product filtering (price, category)
Sorting (low to high)
🔹 2. Social media apps
Searching users/posts
Feed filtering
🔹 3. Admin dashboards
Pagination (page, limit)
Reports filtering
🔹 4. APIs (Backend services)
Data fetching with conditions
Dynamic queries
🔹 5. Analytics systems
Filter data by date, type, etc.

👉 Interview answer:

In companies, query parameters are used in APIs for searching, filtering, sorting, pagination, and fetching dynamic data based on user input.
